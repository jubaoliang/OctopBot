# OctopBot App Icons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Expo template launcher artwork with production-ready Octop icons for current iOS, legacy iOS, Android adaptive launchers, and Android themed icons.

**Architecture:** Keep one cleaned vector C master under `assets/branding/`, use it as the foreground for an Icon Composer document, and generate matching opaque/transparent PNG layers with the already installed ImageMagick `magick` command. Preserve all unrelated application configuration and do not modify the upstream Octop checkout.

**Tech Stack:** SVG, Apple Icon Composer JSON, Android adaptive icons, Expo config, Node.js built-ins, ImageMagick, Android emulator/adb.

**Source specification:** `docs/superpowers/specs/2026-11-12-app-icons-design.md`

**Commit boundary:** Do not run `git commit` unless the user explicitly requests it. If a commit is later requested, stage only icon-related files and complete the repository's required `ocr review --audience agent` gate first.

### Task 3: Generate and validate Android adaptive and monochrome layers

**Files:**

- Modify: `assets/images/android-icon-background.png`
- Modify: `assets/images/android-icon-foreground.png`
- Modify: `assets/images/android-icon-monochrome.png`

- [ ] **Step 1: Run the raster contract test before generation**

Run:

```bash
node -e "const {execFileSync}=require('node:child_process'); for (const f of ['assets/images/android-icon-background.png','assets/images/android-icon-foreground.png','assets/images/android-icon-monochrome.png']) { const out=execFileSync('magick',['identify','-format','%w %h %[opaque]',f],{encoding:'utf8'}); const [w,h,opaque]=out.split(' '); if (w !== '1024' || h !== '1024') throw new Error(f+' dimensions: '+out); if (f.includes('background') && opaque !== 'True') throw new Error(f+' must be opaque'); } const box=execFileSync('magick',['assets/images/android-icon-foreground.png','-trim','-format','%@','info:'],{encoding:'utf8'}); const m=box.match(/(\d+)x(\d+)\+(\d+)\+(\d+)/); if (!m) throw new Error('foreground has no visible silhouette'); const [,w,h,x,y]=m.map(Number); if (w < 580 || w > 590 || x < 171 || y < 171 || x+w > 853 || y+h > 853) throw new Error('foreground outside safe zone: '+box); console.log('Android raster contract valid:',box);"
```

Expected: FAIL because the template foreground does not have the required 1024×1024 dimensions.

- [ ] **Step 2: Generate matching 1024×1024 layers**

Run:

```bash
magick -size 1024x1024 gradient:'#FF6466-#FF0004' -colorspace sRGB PNG24:assets/images/android-icon-background.png
magick -size 1024x1024 xc:none \
  \( assets/branding/octop-mark.svg -resize 588x \) \
  -gravity center -composite PNG32:assets/images/android-icon-foreground.png
cp assets/images/android-icon-foreground.png assets/images/android-icon-monochrome.png
```

The 588-pixel visible width is 62 dp on the 108 dp model (`62 / 108 × 1024 ≈ 588`). Centering leaves the complete silhouette inside the central safe zone.

- [ ] **Step 3: Re-run the raster contract and opacity tests**

Run the command from Step 1, then:

```bash
magick identify -format '%f: %wx%h, opaque=%[opaque]\n' assets/images/android-icon-background.png assets/images/android-icon-foreground.png assets/images/android-icon-monochrome.png
```

Expected:

- `Android raster contract valid` with a trimmed box approximately 588 pixels wide near the canvas center.
- Background is `1024x1024, opaque=True`.
- Foreground and monochrome are `1024x1024, opaque=False`.

Open the foreground and monochrome images visually. Expected: identical white silhouette and placement on transparency.
